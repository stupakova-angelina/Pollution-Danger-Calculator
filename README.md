# Pollution Danger Calculator

Простой консольный калькулятор оценки опасности загрязнения окружающей среды.  
Проект показывает, как на понятной логике (без сложных библиотек) реализовать экспертную систему: по паре «сфера + загрязнитель» программа выдаёт процент опасности, уровень угрозы, рекомендации и срок восстановления природы.

## Возможности

- Ввод данных через консоль (`input`) — максимально просто для запуска.
- Оценка опасности по экспертной шкале (0–100%).
- Вывод уровня угрозы: низкий / средний / высокий / максимальный.
- Рекомендации по устранению загрязнения.
- Прогноз срока восстановления экосистемы.
- Легко расширять: новые пары «сфера + загрязнение» добавляются одним блоком `elif`.

## Ограничения 

Этот проект — **учебный прототип экспертной системы**, а не сертифицированный инструмент экологического моделирования.

- Данные — экспертные шкалы.Базовые баллы и коэффициенты уязвимости подобраны по открытым источникам и упрощённым методикам ранжирования рисков.
- Нет учёта внешних факторов.Не учитываются температура, течения, биоразнообразие, тип почвы, сезонность и т.д.
- Сроки восстановления — оценочные.Они отражают порядок величины (десятки, сотни, тысячи лет), а не точный прогноз.
- Не заменяет экологическую экспертизу.Для реальных задач нужны сертифицированные методики и полевые данные.

## Источники данных и методика

Методика построена на упрощённом ранжировании рисков:

- Базовые баллы опасности — по шкалам токсичности и стойкости загрязнителей (упрощённые аналоги подходов к оценке рисков).
- Коэффициенты уязвимости сфер — экспертно, с учётом чувствительности сред (вода > воздух > почва для нефтепродуктов).
- Сроки восстановления — по открытым данным о самоочищении экосистем и периодах полураспада загрязнителей.
  
## План расширения тестов

Проект развивается как инженерная задача: новые сценарии добавляются не «наугад», а по принципу проверки граничных и критических случаев.

### Приоритетные новые тесты 

| № | Сфера | Загрязнитель | Цель теста | Ожидаемый эффект |
|---|-------|----------------|-------------|------------------|
| 1 | вода | ртуть | Проверить работу с высокотоксичными веществами | Опасность должна быть 100%, уровень — МАКСИМАЛЬНЫЙ, срок восстановления — очень долгий (например, 5000 лет) |
| 2 | почва | тяжёлые металлы | Проверить поведение для медленно разлагающихся веществ | Высокий уровень, длительный срок восстановления (сотни лет) |
| 3 | воздух | сажа | Проверить сценарий с быстрым распространением и локальным эффектом | Высокий/максимальный уровень, короткий срок восстановления из‑за рассеивания (но серьёзный вред здоровью) |
| 4 | вода | микропластик | Проверить «накопительный» тип загрязнения | Высокий уровень даже при низкой концентрации, очень долгий срок восстановления |

Такой подход позволяет быстро наращивать покрытие тестами, не ломая существующую логику.

### Дополнительные идеи для тестов

- **Проверка устойчивости к «некорректному» вводу**: разные варианты написания (например, «Нефть», « НЕФТЬ », «нефть/мазут») — чтобы убедиться, что `.lower()` и `.strip()` работают корректно.
- **Граничные значения коэффициентов**: подбор таких коэффициентов, чтобы опасность была ровно на границе уровней (например, 59% → «средний», 60% → «высокий»). Это полезно для проверки логики классификации.
- **Пакетная проверка**: позже можно будет сделать скрипт, который читает `tests.txt` и автоматически сравнивает вывод — это уже следующий уровень автоматизации.

## Идеи для развития

Проект легко расширять. Возможные направления:

- Добавить геоданные.Привязка к координатам и типу местности (например, тундра восстанавливается медленнее степи).
- Учесть климатические параметры.Температура, осадки, скорость ветра — чтобы точнее прогнозировать распространение и скорость разложения.
- Сделать ввод из файла.JSON/CSV с несколькими сценариями для пакетной обработки.
- Добавить визуализацию.Простые графики или тепловые карты (например, через `matplotlib`) для сравнения сценариев.
- Подключить внешние API.Данные о качестве воздуха/воды из открытых источников для актуализации коэффициентов.
- Автоматизировать тесты.Добавить `pytest` и набор автоматических проверок на граничные случаи.
